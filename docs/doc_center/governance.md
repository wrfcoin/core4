# Governance Framework

**Date Created:** May 18, 2025  
**Last Edited:** May 26, 2025

This document outlines the decentralized governance structure of Wrfcoin, detailing the voting
system, proposal mechanisms, treasury management, and how community members can participate in
network governance.

## Governance Philosophy

The Wrfcoin governance model is designed around several core principles:

1. **Progressive Decentralization**: The governance system begins with Foundation oversight and
   gradually transitions to full community control.
2. **Qualified Participation**: Voting power is determined by a combination of token holdings,
   reputation, and activity within the ecosystem.
3. **Transparent Decision Making**: All governance activities including proposals, voting, and
   treasury movements are recorded on-chain.
4. **Inclusive Representation**: Multiple stakeholder groups have representation, including token
   holders, validators, data providers, developers, and research institutions.
5. **Long-term Sustainability**: Governance mechanisms prioritize the long-term health and growth of
   the ecosystem.

## Governance Timeline

The Wrfcoin governance model follows a predetermined evolution:

### Phase 1: Foundation Governance (Years 1-3)

- Wrfcoin Foundation maintains veto power over all proposals
- Minimal on-chain governance with focus on technical upgrades
- Foundation Council makes most decisions with community input

### Phase 2: Hybrid Governance (Years 4-7)

- Introduction of on-chain voting for non-critical parameters
- Foundation retains veto power only for critical/security decisions
- Elected Technical Committee assumes responsibility for protocol upgrades

### Phase 3: DAO Governance (Years 8-10)

- Foundation transitions to advisory role
- Full on-chain governance for all decisions
- Introduction of delegated voting and reputation-based voting power

### Phase 4: Mature Governance (Year 10+)

- Complete community control through mature DAO mechanisms
- Foundation's veto rights expire completely
- Multi-layered governance enabling different voting mechanisms for different types of decisions

## Voting System

### Vote Types

The Wrfcoin governance system supports multiple vote types:

1. **Parameter Changes**: Modifications to protocol parameters (e.g., block size, transaction fees)
2. **Protocol Upgrades**: Core software upgrades that affect consensus
3. **Treasury Proposals**: Requests for funding from the community treasury
4. **Validator Rules**: Changes to validator requirements and rewards
5. **Constitutional Changes**: Modifications to the governance framework itself

### Voting Power Calculation

Voting power is determined by a weighted formula:

```
Voting Power = sqrt(Token Holdings) × Reputation Factor × Activity Multiplier
```

Where:

- **Token Holdings**: The number of WRF tokens held or staked
- **Reputation Factor**: Score based on historical contributions (0.5-2.0)
- **Activity Multiplier**: Based on recent participation (0.8-1.2)

This quadratic voting approach prevents plutocracy while rewarding active participation.

### Voting Process

1. **Proposal Submission**: Anyone can submit a proposal by staking a minimum amount of WRF tokens
2. **Discussion Period**: 7-day period for community discussion and proposal refinement
3. **Voting Period**: 7-day period for casting votes
4. **Execution Delay**: 3-day delay before implementation (allows for emergency intervention if
   needed)
5. **Implementation**: Automatic execution of approved proposals

### Approval Thresholds

Different proposal types have different approval requirements:

| Proposal Type          | Approval Threshold | Minimum Participation |
| ---------------------- | ------------------ | --------------------- |
| Parameter Changes      | >50%               | 15%                   |
| Protocol Upgrades      | >66.7%             | 25%                   |
| Treasury Proposals     | >50%               | 20%                   |
| Validator Rules        | >60%               | 35% of validators     |
| Constitutional Changes | >75%               | 40%                   |

## Treasury Management

The Wrfcoin treasury receives funds from:

1. A portion of transaction fees (10%)
2. Block rewards allocation (5%)
3. Initial token allocation (15% of total supply)
4. Donations and grants

### Funding Categories

Treasury funds are allocated across these categories:

- **Core Development** (40%): Funding for protocol development
- **Ecosystem Growth** (25%): Grants for applications and integrations
- **Research** (20%): Meteorological and climate research initiatives
- **Community** (10%): Education, events, and outreach
- **Emergency Reserve** (5%): Protected funds for critical needs

### Funding Request Process

To request funding from the treasury:

1. **Pre-proposal**: Submit a lightweight proposal to gauge interest
2. **Formal Proposal**: Detailed proposal including:
   - Project description and goals
   - Team qualifications
   - Detailed budget and milestones
   - Expected impact on the ecosystem
   - Timeline and deliverables
3. **Community Review**: Public discussion and feedback
4. **Formal Vote**: On-chain voting by governance participants
5. **Milestone-Based Disbursement**: Funds released as milestones are achieved

## Proposal System

### Proposal Types

The governance system supports various proposal formats:

1. **Signaling Proposals**: Non-binding votes to gauge community sentiment
2. **Parameter Change Proposals**: Specific changes to protocol parameters
3. **Code Upgrade Proposals**: Changes to the protocol's codebase
4. **Treasury Proposals**: Requests for funding
5. **Text Proposals**: General proposals that don't fit other categories

### Proposal Lifecycle

Proposals move through these stages:

1. **Draft**: Initial proposal formation and informal feedback
2. **Submitted**: Formally submitted to the governance system
3. **Voting**: Active voting period
4. **Accepted/Rejected**: Final outcome after voting concludes
5. **Queued**: Waiting for implementation timelock
6. **Executed**: Changes implemented in the protocol

### Creating Effective Proposals

Guidelines for creating governance proposals:

1. **Research thoroughly**: Understand the current state and impact of changes
2. **Consult stakeholders**: Gather input from affected parties
3. **Be specific**: Clearly define what will change and how
4. **Provide rationale**: Explain why the change is beneficial
5. **Consider alternatives**: Address other approaches that were considered
6. **Define success metrics**: How outcomes will be measured
7. **Timeline and resources**: What's needed for implementation

## Governance Participation

### How to Participate

Community members can engage in governance through:

1. **Voting**: Cast votes on active proposals
2. **Proposal Creation**: Submit new governance proposals
3. **Discussion**: Participate in governance forums and calls
4. **Delegation**: Delegate voting power to trusted representatives
5. **Technical Contribution**: Implement approved changes

### Governance Tools

The following tools support governance participation:

- **Governance Portal**: Web interface for all governance activities
- **Governance Forum**: Discussion platform for proposals
- **Voting Dashboard**: Track voting power and history
- **Governance Explorer**: View all historical proposals and outcomes
- **Delegation Platform**: Manage voting delegation

### Governance Best Practices

1. **Stay informed**: Follow governance discussions and proposals
2. **Vote regularly**: Active participation strengthens the ecosystem
3. **Delegate thoughtfully**: If delegating, choose representatives who align with your values
4. **Contribute constructively**: Focus on the long-term health of the network
5. **Consider all stakeholders**: Think beyond your immediate interests

## Dispute Resolution

When governance conflicts arise:

1. **Community Mediation**: Facilitated discussion to reach consensus
2. **Technical Advisory Committee**: Expert input on technical disputes
3. **Multi-signature Override**: Emergency action by elected guardians (only for critical security
   issues)
4. **Foundation Intervention**: During transition phases only
5. **Fork Choice**: As a last resort, community can choose between competing implementations

## Future Governance Evolution

The governance system itself will evolve through:

1. **Governance Experiments**: Controlled tests of new mechanisms
2. **Regular Reviews**: Scheduled evaluations of governance effectiveness
3. **Progressive Decentralization**: Gradual reduction of centralized control
4. **Cross-chain Governance**: Integration with broader ecosystem governance
5. **AI-augmented Governance**: Exploration of AI tools to improve governance processes
